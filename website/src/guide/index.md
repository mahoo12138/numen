# 认识 Numen

Numen 是一个以插件为基础的个人自动化运行时。你可以在 Workbench 中组合触发器、数据处理和外部操作，发布固定版本，再交给运行时接收事件、调度执行并保存记录。

一个典型流程是：Webhook 接收业务事件，整理字段，计算日期，最后生成 JSON。需要消息与通知时，也可以用 MQTT 触发、生成 CSV，再通过 SMTP 提交邮件。

## 从事件到结果

| 阶段 | 你做什么 | Numen 保存什么 |
| --- | --- | --- |
| 编排 | 添加能力、配置参数、连接数据引用 | 可继续修改的 Draft |
| 发布 | 检查问题，发布并激活版本 | 固定的 Revision 与执行计划 |
| 接收 | 启用流程，等待 Trigger 事件 | 事件接受记录与 Run |
| 执行 | 查看运行状态和节点输出 | Execution、Attempt 与事件时间线 |

编辑草稿不会改写已接受的运行。停用自动化会停止新的触发订阅，已有运行仍使用原来的版本继续执行。

## 当前可以做什么

- **编排与调试：** 参数表单、字段引用、结构化控制流、图流程、草稿试运行、发布版本试运行与局部测试。
- **本地处理：** JSON 解析与序列化、对象浅合并、数组去重、日期日历运算、CSV 解析与导出。
- **接入事件与服务：** Cron 定时、JSON Webhook、MQTT 推送与发布、HTTP 请求、认证 TLS SMTP 邮件。
- **追踪与恢复：** SQLite 持久记录、超时与重试、取消、重启恢复，以及按流程或业务字段控制运行并发。
- **扩展能力：** 插件注册版本化 Capability，通过 Schema 提供配置表单，并复用 Credential、Connection 和前端扩展契约。

## 版本与适用边界

本站随当前工作区源码维护，功能说明不代表相关包已经发布到 npm。先按源码方式启动；后续发布以仓库发布记录为准。

当前运行模型面向**单节点、单个活跃 Scheduler**。持久接受保证能找到对应的 Run，不等于邮件、HTTP 等外部副作用只发生一次。具体重试、离线消息及提交结果的边界，请查看相应集成说明。

Numen 使用自己的 Capability、表达式和执行模型；它没有 n8n 节点兼容层。当前官方集成也不包含 Google Calendar 或通用 OAuth 授权流程。
